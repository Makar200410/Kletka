# Инструкция для следующего агента

Проект «Клетка» — статический сайт подготовки к ОГЭ и ЕГЭ по 10 предметам. Сборки нет: `index.html` + CSS + обычные JS-скрипты. Репозиторий: https://github.com/Makar200410/Kletka (ветка `main`).

Прочитай этот файл целиком, потом `CONTENT_GUIDE.md` (формат контента) и `LABS_GUIDE.md` (формат лабораторий). Это обязательные спецификации.

---

## 1. Как устроен проект

| Путь | Что там |
|---|---|
| `index.html` | подключает шрифты, KaTeX, все скрипты. У `css/app.css`, `js/viz.js`, `js/app.js` есть `?v=N` — **увеличивай N при каждом изменении этих файлов**, иначе браузер покажет старую версию из кэша |
| `css/app.css` | все стили сайта. Цвета — только через переменные (`--ink`, `--red`, `--ok`, `--warn`, `--text`, `--muted`, `--line`, `--sheet`…), у каждой есть значение для тёмной темы. Буквальные цвета в компонентах не писать |
| `js/app.js` | движок: маршруты `#/…`, прогресс в `localStorage`, 5 типов заданий, пробник, тренажёр ошибок, карточки, поиск, ИИ-репетитор (работает только внутри Claude) |
| `js/data/registry.js` | объявляет `KL.addSubject` |
| `js/data/<предмет>.js` | контент: темы, теория, задания, карточки. Формат — `CONTENT_GUIDE.md` |
| `js/labs/<id>.js` | интерактивные лаборатории. Контракт — `LABS_GUIDE.md` |
| `js/viz.js` | SVG-иллюстрации к теории (графики, геометрия, схемы) и карта, куда их вставлять |
| `tools/validate.js` | проверка контента |

Запуск локально (из папки проекта):

```bash
python -m http.server 8765
```

Затем открыть http://localhost:8765. В Claude Code есть `.claude/launch.json` с конфигурацией `kletka`.

Проверка контента (нужен KaTeX для проверки формул; если пакета нет — поставь во временную папку: `npm i katex@0.16.11`):

```bash
KATEX_PATH=/путь/к/node_modules/katex node tools/validate.js
```

Без `KATEX_PATH` валидатор тоже работает, но формулы не проверяет. Цель — **0 ошибок**.

### 2.4. Иллюстрации к новым темам — СРЕДНИЙ
Как добавить рисунок:
1. В `js/viz.js` добавь в объект `F`:
   ```js
   F['my-fig'] = { cap: 'Подпись под рисунком', svg: function () {
     return plot({ x: [-3, 3], y: [-2, 4], fns: [{ f: function (x) { return x * x; }, c: 'c1', label: [1.5, 3, 'y = x²'] }] });
   } };
   ```
   Помощники: `plot()` — координатная плоскость с графиками; `timeline(события, от, до)` — лента времени; `svg(w, h, тело)`, `L` (линия), `T` (текст), `C` (круг), `P` (path), `poly`, `A` (стрелка), `arc` (дуга угла).
   Классы: линии `c1` синий, `c2` красный, `c3` зелёный, `c4` жёлтый, `c5` цвет текста, модификаторы `thin`, `wide`, `d` (пунктир); заливки `f1`–`f4`, `fs` (фон листа), `fn` (без заливки); точки `p1`, `p2`, `p3`, `p5`; текст `t`, `ts` (мелкий), `tn` (цифры), `tb` (жирный), `ti`/`tr`/`tg`/`tm` (цвет). **Не писать буквальные цвета** — иначе сломается тёмная тема.
2. В `KL.viz.map` укажи, куда вставить: `'id-темы': { номер_раздела: ['my-fig'] }` (раздел считается с 0).
   Или вставь прямо в текст теории: `<div class="viz" data-viz="my-fig"></div>`.
3. Проверка: `node --check js/viz.js`, потом открыть тему в браузере.

Идеи для новых тем: схема Н/НН, пунктуационные схемы предложений, граф для информатики, ветви власти РФ, структурные формулы органики, карта фронтов ВОВ (схематично).

## 3. Правила работы

1. **Каждый агент — только в своих файлах.** Если вас несколько: один пишет `js/data/russian.js`, другой — `js/labs/truth.js` и т. д. Общие файлы (`index.html`, `css/app.css`, `js/app.js`, `js/viz.js`) правит один, в конце.
2. Большой файл пиши частями (Write, затем Edit), в итоге один вызов `KL.addSubject`.
3. Строки с LaTeX и обратными слэшами — через `String.raw\`…\``; внутри нельзя `` ` `` и `${`.
4. После правок: валидатор → 0 ошибок; `node --check` для каждого изменённого JS; просмотр в браузере (светлая и тёмная тема, мобильная ширина).
5. Подними `?v=N` в `index.html` для изменённых общих файлов.
6. Коммит и отправка:
   ```bash
   git add -A && git commit -m "Что сделано" && git push
   ```
   В конце сообщения коммита — строка соавторства, если её требует среда.
7. Лимиты: владелец просит работать экономно. Не запускай больше 3–4 параллельных агентов, давай каждому конкретный список файлов и тем из раздела 2.

## 5. Иллюстрации в отдельных файлах и микротемы (новое)

**Иллюстрации по предметам.** Общий `js/viz.js` больше не правят параллельные агенты. Каждый предмет имеет свой файл `js/viz/<предмет>.js` (уже подключён в `index.html`). В нём:

```js
F['my-fig'] = { cap: 'Подпись под рисунком', svg: function () { return svg(600, 240, L(...) + T(...)); } };
V.addMap('id-темы', { 2: ['my-fig'] });   // 2 = номер раздела теории (с нуля)
```

Доступны помощники `svg, L, T, C, P, poly, A, arc, plot, timeline, box, sector, bell` (описание — в разделе 2.4). Классы цветов — только из `css/app.css` (раздел «Иллюстрации»), буквальные цвета запрещены. Проверка: `node tools/check-viz.js` — вызывает все рисунки, ищет NaN, текст вне рамки, ссылки на несуществующие темы и разделы. Цель — 0 ошибок. Если нужен рисунок в коде из другого предмета — не правьте чужой файл.

**Микротемы.** Теорию пишем короткими темами (10–15 минут чтения, 3–5 разделов, у каждого раздела один главный вывод), а не огромными главами. Одна микротема = одно задание КИМ или один приём. В названии темы — конкретный вопрос («Правописание корней -лаг-/-лож-», а не «Орфография»). 9–12 заданий, минимум три типа. **Иллюстраций — как можно больше:** почти в каждом разделе теории по рисунку (минимум 3–4 на тему): схемы, графики, инфографика-таблицы, пошаговые схемы решения задач, деревья решений, ленты времени. Ученик должен понять тему по рисункам, а не только по тексту.

**Как работать нескольким агентам.** Каждый агент правит только свой файл `js/data/<предмет>.js` и свой `js/viz/<предмет>.js`. Общие файлы (`index.html`, `css/app.css`, `js/app.js`, `js/viz.js`, `tools/`, документация) не трогать. После работы: `node --check` для своих файлов, `node tools/validate.js js/data/<предмет>.js` (0 ошибок), `node tools/check-viz.js` (0 ошибок). Не запускать `git` — коммитит координатор.
